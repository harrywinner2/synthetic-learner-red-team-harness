- **Decision: deploy target = Railway.** Rationale: this is a Python/FastAPI backend that runs long multi-turn LLM simulations and needs a persistent DB (learner state + interaction log). Railway = one always-on service + Postgres, no serverless timeout. (Demo DB defaults to SQLite for portability; Postgres optional via DATABASE_URL.)
- **Decision: browser tooling = local Playwright + Chromium** for style capture, live-verify, demo recording.
- **Decision: sim scope = hybrid.** Ship a clearly-badged *cached* baseline↔improved comparison (instant, free to view) PLUS a prominent "Force live run" control that fires real OpenAI calls. Cached status is shown in the UI and called out in narration — honesty is the product's whole thesis.
- **Decision: subject under test = Algebra I, linear equations & slope.** Rationale: dense, well-documented misconception literature (reversal error, slope-as-"number-in-front-of-x", rate vs intercept, equality-as-operator) and squarely in Varsity Tutors' K-12 / test-prep territory.
- **Decision: frontend = polished single-page app in vanilla HTML/CSS/JS with hand-rolled SVG charts** (no CDN dependency, so the mockup opens offline and the deployed app renders identically), served as static by FastAPI. One deploy, full control over the "expressive" look.
