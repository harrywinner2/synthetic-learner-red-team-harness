# Decision Log

The reasoning behind the choices that shaped the harness. Chronological-ish; the running
build trail is in `../BUILD_LOG.md`.

### Subject under test — Algebra I, linear relationships & slope
Picked for the density and replication quality of its misconception literature (reversal
error, slope-as-"number-in-front-of-x", rate-vs-intercept, equality-as-operator) and its fit
with Varsity Tutors' K-12 / test-prep market. A subject with *well-documented wrong answers*
lets us seed misconceptions that are defensible rather than invented.

### Learners are LLM agents, but on a deterministic leash
The tempting design is "spin up agents and let them role-play students." That fails the
brief's own warning about "a swarm of obedient fake students." Instead, a persona's trait
vector deterministically chooses the *move* each turn (attempt / ask for answer / fake
understanding / change topic / bypass); the LLM only renders that move in character. We get
authentic-looking transcripts and reproducible, inspectable behaviour.

### Learning is a hidden latent-variable model, not the LLM's self-report
This is the core credibility decision. Each learner has a hidden BKT-style mastery the tutor
never sees. Test scores are the *expected accuracy* that latent state predicts. So "did the
student learn" is reproducible arithmetic governed by a model we control — which is the
honest answer to "why should we trust the synthetic results." Giving the answer barely moves
mastery; probing a misconception is what repairs it.

### Measure learning as transfer, not local correctness
A pre → instruction → post → **transfer** (novel framing) design. Transfer items get no guess
floor and a penalty, and certain personas (Memorizer, Confident Guesser) carry an explicit
transfer deficit, so "passes the practiced item, fails the re-framed one" actually shows up.

### Avoidance episodes & recovery measured from the ground-truth move; classifier validated against it
Recovery rate is computed from the learner's known action (and is therefore directly sensitive
to the tutor's redirection policy). The LLM avoidance classifier reads only the *text* and we
report how often it agrees with the ground-truth move — i.e. we test whether avoidance is even
detectable, instead of assuming it.

### Every headline metric ships with a counter-metric
Learning gain ↔ transfer gap; answer-giving ↔ learning; hint-laddering ↔ independence;
trained ↔ held-out; primary evaluator ↔ independent judge. The verdict is a rules engine over
these pairs, not a single score.

### Human-in-the-loop improvement (not full auto)
The Diagnostician *proposes* policy edits and the loop applies a curated v1. The brief rewards
judgment over autonomy theater, and a proposal-and-approve loop is what a real tutoring team
would actually run.

### Two held-out personas, held-out problems
Over-hinter and Adversarial Bypasser are excluded from the cohort the fix is tuned against, so
the comparison can detect overfitting to the synthetic learners — the failure the brief
specifically calls out.

### Cached run = a real recording, clearly labelled
The default view is a committed recording of a genuine experiment (real model dialogue + real
judges), regenerated by `scripts/generate_fixture.py`, so the demo is instant and free to view.
It is badged "cached" in the UI and called out in narration; a live run reproduces it for real.
(Per client direction: cached must be disclosed, and a force-live path must exist.)

### Stack & deploy — FastAPI + single-file SPA on Railway
One always-on Python service runs multi-turn LLM simulations and owns a persistent DB (learner
state + interaction log); serverless timeouts make that awkward elsewhere. The frontend is one
self-contained file extended from the design mockup, served as static by the same service —
one deploy, one URL.

### Model — OpenAI gpt-4o-mini
Cheap and more than capable for this task; the provider is abstracted and the model is a single
env var. The independent judge can be pointed at a different model for genuine independence.
